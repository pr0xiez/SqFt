## Architecture

### Multi-tenancy
Every data model has an `orgId` field. All API routes call `getOrgId()` from `lib/tenant.ts` before querying, scoping every Prisma query to `{ where: { orgId } }`. Users belong to one organization. Organizations are isolated — no cross-tenant data access is possible.

### Offline strategy
No custom service worker logic is written by hand. `@ducanh2912/next-pwa` generates the service worker at build time from the Next.js output. The SW uses cache-first for the app shell and static assets. TanStack Query handles data: in-memory cache serves stale data while offline; a TanStack Query IDB persister (Phase 6) will persist the cache across sessions.

### Auth flow
1. `POST /api/auth/signup` → creates `Organization` + `User` (owner role)
2. `GET /onboarding` → user sets company name → `POST /api/org/setup`
3. `POST /api/auth/signin` (NextAuth credentials) → JWT with `{ userId, orgId, role }`
4. `proxy.ts` protects all `/(app)/*` routes; redirects unauthenticated users to `/login`

## Business Logic (`lib/utils.ts`)

All ported verbatim from prototype — pure functions, no side effects:

| Function | Description |
|---|---|
| `parsef(v)` | Parse float from string input; null if invalid |
| `fmtBig(n)` | Format large currency ("$4,250") |
| `fmtDollar(n)` | Format currency with cents ("$42.50") |
| `roomSqft(room)` | Area for rect / tri / lshape room |
| `lshapeNet(data)` | L-shape area = sum(sections) − sum(deductions) |
| `estTotalArea(items)` | Sum all room sqft in an estimate |
| `getEffectiveQty(li, rooms)` | Qty = manual value OR linked rooms × (1 + waste%) |
| `liSubtotal(li, rooms)` | effectiveQty × rate |
| `getWeekStart(date)` | Monday of the week containing date |
| `todayStr()` | Today as YYYY-MM-DD |
| `getGreeting()` | "Good morning/afternoon/evening" |
